## 它解决什么问题

普通画图工具里，架构图、需求图、流程图、部署图各自存一份图数据：四份副本、四次修改，漏改一次图就过期。

Nousay 不存任何一张图的数据。需求、功能、服务、数据都以**实体与关系**写进同一份本体，由 AI 经 MCP 生成与更新；工具不画图，只把这同一份数据**投影**成图。

```
普通画图工具   4 份副本 · 4 次修改 · 3 次容易漏
Nousay        1 份本体 · 1 次修改 · 0 份副本
```

## 工作机制

1. **WRITE · AI 经 MCP 写入** — 在 MCP 客户端里说清设计，AI 生成与更新需求、功能、服务、数据这些实体和它们的关系。
2. **SOURCE · 本体是唯一数据源** — 只保存实体、关系与属性，不保存任何一张图的数据。
3. **PROJECT · 投影成图** — 同一份本体按视图模板渲染，四张图看到的是同一批实体。

改一处，四张图同时重新投影。

## 核心能力

### 四族视图（已具备）

| 图族 | 内容 |
| --- | --- |
| 需求全景 | 需求域全景（样例：114 节点 / 227 关系） |
| 流程与状态 | 业务流程 + 技术流程（样例：销售出库 5 节点 / 13 节点） |
| 技术架构 | 技术域分层架构（样例：39 节点 / 6 段分层） |
| 部署架构 | 部署域拓扑（样例：33 节点 / 26 关系） |

### 其它能力

- **多项目一览** — 项目概览页顶部指标行直接呈现本体数量：项目、需求 + 功能点、场景、页面 + 页面功能、业务流程。
- **完成状态** — 概览页逐域打分：需求、设计、流程、部署，没做的写 0。
- **链路高亮** — 在图里点一个节点，它和上下游一起亮，其余压淡。

## 快速开始（三步拿到第一张图）

1. **下载并安装桌面宿主** — 安装后项目数据默认落在本机。
2. **装载插件包** — 宿主自带安装说明，由外部 AI 经 MCP 装载图设计插件包，不需要手动配置服务端。
3. **说清项目，生成第一张图** — 在 MCP 客户端里补齐需求、功能与服务，需求全景图随即投影出来；其余图族按同一份本体补齐。

## 适合谁

- **架构设计师** — 把分层、依赖与部署讲成一套图，而不是四张各自为政的截图。
- **全栈设计师** — 从需求走到部署，自己走完整条链路，不必等别人补文档。
- **正在做方案评审** — 图能对齐讨论，不用反复解释「这张图是哪一版」。
- **重视数据主权** — 设计资料留在自己电脑上，不经任何服务端。

## 常见问题

**它和 Figma、draw.io 有什么区别？**
那些工具存的是一张张图，数据随图保存。Nousay 存的是本体：实体、关系、属性。图只是投影，所以同一件事只有一份数据。

**我的设计数据存在哪里？**
存在你本机的项目库里，跟项目走。不经过服务端，也没有账号体系强制上传。

**断网还能用吗？**
图谱与各类视图在本地打开，断网可看。需要 AI 写入时，再连上你自己选择的模型。
